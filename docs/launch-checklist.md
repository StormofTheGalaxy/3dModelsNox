Критерий приёмки фазы 7 (§7): чек-лист закрыт, админ управляет платформой
без доступа к коду.

фаз и post-MVP модулей. Пункты с пометкой «вручную» закрывает человек перед
запуском: код за них отвечать не может.

## Post-MVP: что включать в бете

Двенадцать модулей из §7 готовы и лежат за флагами, по умолчанию
выключенными. Включение — решение владельца, а не разработчика: каждый
флаг меняет то, что видит пользователь, а часть из них требует внешних
условий.

Включаются свободно — работают на заглушках или без внешних сервисов:

- [ ] `feature_auction` — торги по заказу, оба режима
- [ ] `feature_work_comments` — комментарии к работам
- [ ] `feature_public_templates` — каталог шаблонов ТЗ
- [ ] `feature_organizations` — команды, студии, менеджеры заказчика
- [ ] `feature_achievement_builder` — конструктор достижений в админке
- [ ] `feature_promotions` — буст и featured (выдаются вручную)
- [ ] `feature_subscriptions` — тарифы с надбавками (выдаются вручную)

Требуют внешней настройки — включать после того, как она сделана:

- [ ] `feature_telegram` — нужен токен бота и зарегистрированный вебхук
      (`npm run telegram:webhook`)
- [ ] `feature_pwa` — нужна пара ключей VAPID (`npm run push:keys`), иначе
      подписка оформится на заглушечный ключ и уведомления не придут
- [ ] `feature_brief_chat`, `feature_ai_matching`, `feature_ai_assistant` —
      работают на детерминированной заглушке без ключа OpenAI, но
      пользователю в этом режиме честно показывается предупреждение;
      для беты нужен `OPENAI_API_KEY`

Включать нельзя до появления юрлица (ADR 0019, ADR 0020):

- [ ] `feature_payments` — платёжный модуль; сегодня существует только
      ручной режим, и он же поведение по умолчанию
- [ ] `feature_commissions` — комиссии платформы; §1.2.1 прямо запрещает
      их до юрлица
